Development skill

Ponytail dev

Updated Oct 23, 2026

Make the smallest correct development change and match the proof to its risk.

Use this skill when

  • You are implementing, fixing, refactoring, testing, or reviewing software.
  • The design is already approved and must remain fixed during implementation.
  • You need evidence that matches the change's impact and recovery cost.

Working rules

Keep the change small

Prefer existing patterns, standard features, and installed dependencies. Add only what the requirement needs.

Fix the cause

Understand the affected flow, inspect callers, and repair a shared cause when evidence supports that scope.

Protect safeguards

Keep security, accessibility, data-loss protection, and required error handling intact.

Prove the result

Use a focused test, build, type check, linter, probe, or direct behavior check. Broaden checks only when risk requires it.
