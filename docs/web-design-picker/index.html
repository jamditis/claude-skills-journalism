Web design picker

Build separate website design theses, compare them in one client review site, and deliver the selected direction with its assets and deployment package.

What it makes

A review package that lets people judge different design arguments in context, then hand off the useful source files without mixing them into the deployment archive.

  • 01Two to five standalone responsive concepts, three by default.
  • 02A fullscreen picker with keyboard navigation, URL state, and isolated concept styles.
  • 03A searchable asset catalog with individual, family, and download-all controls.
  • 04Static QA reports, desktop and mobile previews, and separate deployment and handoff ZIPs.

Distinct by design

Each direction changes the information architecture, type, space, geometry, media, interaction, and emotional register. A palette swap does not count.

Evidence-led

Proof, process, and outcomes lead the page.

Editorial

Reading rhythm and narrative sequence carry the argument.

Product-first

The interface and its working parts become the evidence.

Install and run

Claude Code marketplace

/plugin marketplace add jamditis/claude-skills-journalism

Start a project

python scripts/web_design_picker.py init ./client-site --name "Client name"
python scripts/web_design_picker.py run ./client-site --strict --test-downloads

Scaffolding and favicon exports require Pillow and resvg-cli. Browser previews require Playwright and Chromium. Video exports require ffmpeg. Generated sites are framework-free static files.

Release boundary

The Cloudflare Drop ZIP starts with index.html and contains only deployable static files. The design-assets ZIP holds editable artwork, tokens, notes, and source derivatives.

Prototype forms must state that they are not connected or download a structured brief. Production submission needs a real endpoint. The QA report records what ran and does not label browser previews complete when Chromium could not open the local test server.
