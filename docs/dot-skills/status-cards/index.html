The workflow

  1. Read the original post and its full thread. Confirm bot ownership, the exact destination, scope and existing permissions.
  2. Check primary evidence. Distinguish source capability, deployment, runtime activation and ordinary-role acceptance. A merge alone proves none of the latter.
  3. Render the full graphic and inspect text, contrast, clipping, exact progress endpoints and accessible fallback.
  4. Upload to the authorized private staging thread as the same bot. Read back the message and actual Slack file identity.
  5. Edit only the authorized original post. Verify its timestamp is unchanged and its image points to the new file.

Keep two clocks separate

Last checked records a successful evidence check. Last progress change records a changed estimate or milestone. A failed retrieval must not move the successful-check timestamp.

Stop conditions

Stop on an explicit denial, unknown ownership or an uncertain send. Inspect the outcome before any permitted retry. Private staging is still a message and can notify its participants.
