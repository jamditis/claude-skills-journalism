Reusable methods need visible boundaries. These notes distinguish a practical workaround from a verified product fix.

Private staging is still communication

The public report #58068 and its recorded workaround document a private upload followed by replacement of the original bot-owned image. That route can avoid a second public post. It still creates a private staging message.

This page does not declare the original limitation resolved or promise that the workaround works in every environment. Read the current issue discussion before relying on it.

A skill is not permission

Downloaded instructions do not transfer credentials, account access, authorizations or saved approval rules. Verify the destination, audience, data and action for your own workflow.

An uncertain send is not a failed send

Read the destination before retrying. If the outcome remains unknown, stop rather than create a duplicate. Do not switch identities or routes to bypass a denial.

A scheduled wake-up is not a successful check

Update evidence freshness only after the necessary evidence was read successfully. Keep the last reliable time when essential retrieval fails.

Passing one check is not a full validation

State which checks ran, which passed and which were blocked. A static package inspection is not a runtime test. A merged change is not deployment or staff acceptance.

Portability has limits

Tool names, connectors, filesystem paths, hooks and schedules vary by app. Treat these as environment requirements, not portable promises. Replace private examples with your own verified configuration.

Help improve the guide

Report a reproducible issue with redacted inputs, the expected result and the observed result. Never publish private support correspondence, credentials or account identifiers in a public issue.
