## Modifications from upstream

**v1.0.0 milestone (independent of upstream `superpowers` plugin).** Decouples superjawn's runtime dispatch from the upstream `superpowers` plugin. The v0.6.0 release left four `superpowers:code-reviewer` agent dispatches in place (three in `requesting-code-review/SKILL.md`, one in `subagent-driven-development/code-quality-reviewer-prompt.md`), making the upstream plugin a soft dependency for any session that runs those skills end-to-end. v1.0.0 rewrites all four to `pr-review-toolkit:code-reviewer`, an Anthropic-maintained agent in the `@claude-code-plugins` marketplace whose description and contract overlap with the upstream agent (precisely-crafted-context code review, returns Strengths / Issues / Assessment). After the rewrite, no skill in superjawn references the upstream `superpowers` plugin in a way that requires it to be installed; the v1.0.0 readiness gate in the v0.6.0 divergence log resolves to "rewrite the references" (option 2 of the three listed). Manifest changes: `requesting-code-review` drops `skill_md_parity` from `true` to `false` (the rewrite breaks byte-identity with upstream `requesting-code-review/SKILL.md`); `subagent-driven-development` adds a `supporting_file_overrides` entry for `code-quality-reviewer-prompt.md`. The three remaining example mentions of `superpowers:code-reviewer` in `using-superjawn/references/{codex,copilot}-tools.md` (two in codex-tools, one in copilot-tools) are intentionally preserved as documentation pointing at upstream's canonical agent name; they are not dispatch targets and the validator's cross-ref rule explicitly allows `superpowers:<agent>` references. The original v0.6.0 readiness-gate language ("≥2 weeks of real use after 2026-05-07") was waived by the project owner ahead of v1.0.0 ship; reinstall path for the upstream plugin if a regression surfaces is `/plugin install superpowers@claude-plugins-official`. Issues #47 and #49 (parity-preserved upstream content bugs in `using-git-worktrees` and `finishing-a-development-branch`) and the validator's supporting-file-walk hardening item remain open and are not addressed in v1.0.0.

**v0.2.0 architecture revision.** Research belongs only at entry-point stages where work originates without an upstream artifact. The three foundation skills shipped in v0.1.0 are now categorized:
- `brainstorming`, research phase preserved (entry-point skill)
- `writing-plans`, research phase stripped (consumer of brainstorming spec; trusts the handoff)
- `executing-plans`, per-task drift check replaced with a one-time default-skip freshness check at execution start, gated on three triggers (cross-session plan, external API/service, main/master branch). Two smoke-test bugs from PR #34 review folded in: the execution-journal location is now defined (`.superpowers/exec-journal-<plan-slug>.md`), and the master-branch guardrail is wired into the freshness check itself (was previously only in Remember).
